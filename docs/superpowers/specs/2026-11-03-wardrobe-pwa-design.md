# 我的衣橱 · 本地 PWA 设计规格

- 日期：2026-11-03
- 状态：已确认，待实现
- 范围：个人自用、安卓手机优先、数据完全本地

## 1. 背景与目标

做一个只给自己用的穿搭衣橱应用，解决三个问题：知道自己有哪些衣服、能把单品组合成搭配、记得每天穿了什么。

约束与目标：

- 数据只存在手机本地，不上传云端，不需要账号。
- 主要运行在安卓手机的 Chrome 浏览器中，通过 PWA「添加到主屏幕」使用。
- 电脑浏览器可打开同一套应用，但不是主要使用场景。
- 实现与使用成本尽可能低：免费静态托管、零后端、零构建步骤。
- 视觉采用已选定的「E · 胶片日记」方向：米黄纸张、宝丽来相纸、等宽小标签、轻微颗粒与暖色。

## 2. 功能范围

### 2.1 第一版包含

1. **单品管理**：录入、编辑、删除、收藏、搜索、分类筛选、排序、查看详情。
2. **搭配组合**：多选单品创建搭配、编辑、删除、收藏、查看详情、自动拼贴封面。
3. **穿着记录**：月历查看、按日期记录穿搭、月度统计、单品穿着次数与闲置提醒。
4. **数据备份**：完整导出为单个 JSON 文件，导入覆盖恢复。
5. **PWA**：添加到主屏幕、离线使用、应用图标。

### 2.2 第一版不包含

- 云同步、多设备同步、账号体系。
- 天气 API、AI 推荐、社交分享。
- 价格、购买渠道、洗涤保养等字段。
- 单品多图（每件单品只保留一张主图）。
- 深色主题（E 风格是浅色纸张质感，后续可单独设计暗色纸张主题）。
- 原生 APK 打包（后续可用 Capacitor 复用同一套代码）。

## 3. 用户与核心场景

单一用户：衣橱的所有者。典型操作：

1. 买了一件新衣服，拍照录入，填分类、颜色、季节和场合。
2. 出门前打开搭配页，选一套保存过的搭配，点「今天穿这套」。
3. 晚上补记今天穿了什么，或者翻月历看这个月穿了几天。
4. 想找某件很久没穿的衣服，按「最久未穿」排序或看闲置统计。
5. 换手机或清理浏览器前，导出备份；需要时导入恢复。

## 4. 信息架构与页面

底部固定四栏导航：**衣橱 / 搭配 / 记录 / 我的**。

### 4.1 衣橱（首页）

- 顶部：标题、单品数量、搜索框。
- 筛选：分类横向胶囊（全部 + 各分类）；筛选面板中可叠加季节、场合与「仅看收藏」。
- 排序：最近添加（默认）、最常穿、最久未穿；「最久未穿」把从未穿过的单品按录入时间从早到晚排在前面。
- 内容：双列相纸卡片，展示主图、名称、分类与季节；无图时显示分类占位图。
- 操作：右上「＋」进入录入；点卡片进入单品详情。
- 空状态：引导「拍下第一件衣服」。

### 4.2 单品详情

- 大图相纸展示、名称、编号。
- 标签：分类、颜色、季节、场合、收藏。
- 信息行：品牌、备注。
- 统计：穿过次数、最近穿着、在衣橱天数。
- 操作：记录今天穿它、编辑单品、删除（二次确认）。

### 4.3 单品录入 / 编辑

- 拍照或从相册选择一张图；可在保存前重新选择或移除。
- 字段：名称（必填）、分类、颜色、季节（多选）、场合（多选）、品牌、备注、收藏。
- 保存时进行图片压缩；保存中禁用按钮，防止重复提交。

### 4.4 搭配

- 列表：双列或单列相纸卡片，封面为单品缩略图自动拼贴；显示名称、季节/场合、单品数。
- 新建：填写名称，多选至少一件单品，选择季节与场合，可加备注。
- 详情：拼贴封面、名称、标签、单品清单、穿着统计。
- 操作：今天穿这套、编辑、删除（二次确认）。

### 4.5 记录

- 月历：周一为一周起始；有记录的日期显示小圆点；今天有描边；点击日期查看当天记录。
- 月度统计：本月记录天数、最常穿单品、闲置件数。
- 当天记录卡片：搭配名称（或单品组合）、缩略图、备注、天气标签（手动选择，可选）。
- 记录入口：选择已有搭配，或临时选择若干单品；一天只允许一条记录，再次记录同一天时进入编辑。
- 记录保存时把当时穿的单品 ID 与名称快照写入记录，之后修改搭配不影响历史统计。

### 4.6 我的

- 导出备份、导入备份。
- 存储占用：已用空间、单品数、搭配数、记录数。
- 分类管理与颜色管理：增加、重命名、删除自定义项；删除不影响已使用该值的单品。
- 安装到桌面说明（安卓 Chrome）。
- 关于与版本号、最近备份时间。

## 5. 视觉设计规范

### 5.1 设计令牌

```css
--paper:        #F5E6C8;  /* 页面底色 */
--paper-soft:   #FBF3E2;  /* 次级底色、输入框 */
--card:         #FFFDF6;  /* 相纸卡片 */
--ink:          #3B2F26;  /* 主文字 */
--ink-soft:     #7A6652;  /* 次要文字，对比度 ≥ 4.5:1 */
--line:         #DCCDAF;  /* 细分隔线 */
--line-strong:  #C9B08A;  /* 虚线边框 */
--rust:         #8B5E3C;  /* 主操作色，白字对比度 ≥ 5:1 */
--rust-deep:    #6F4529;  /* 按下态 */
--teal:         #4A7B7C;  /* 次要点缀、日历圆点 */
--rose:         #CFA79B;  /* 装饰色，不用于小字 */
--sand:         #EBD9B8;  /* 标签底色 */
```

- 字体：标题使用 `"Noto Serif SC", "Songti SC", "STSong", serif`；正文使用系统无衬线字体；日期、编号、标签使用 `ui-monospace, Consolas, monospace`。不使用网络字体，保证离线与加载速度。
- 圆角：卡片 4–6px，弹层 10px；不使用大圆角，保持纸张感。
- 阴影：`0 1px 3px rgba(80,60,30,.15)` 与 `1px 3px 7px rgba(80,60,30,.18)`，避免厚重投影。
- 纹理：低透明度横纹 + 暖色径向渐变叠加，不干扰文字阅读。
- 相纸效果：白色 5–6px 内边距，底部留 caption 区；列表卡片可轻微旋转 ±1.5°，详情页大图不旋转，避免点击区域偏移。
- 图标：内联 SVG，24×24 viewBox，线宽 1.6–1.8，禁止使用 emoji 作为图标。
- 动效：150–250ms，`ease-out`；只改变透明度与位移；`prefers-reduced-motion` 下关闭位移与旋转动画。
- 布局：移动优先，内容最大宽度 480px，桌面居中；底部导航固定并处理 `safe-area-inset-bottom`。
- 触控目标不小于 44×44px；正文不小于 16px；标签不小于 12px。

### 5.2 关键组件

- 相纸卡片：图片区 4:5，caption 显示名称与等宽小标签。
- 标签胶囊：沙色底、深棕字；重点标签使用青绿底白字。
- 主按钮：铁锈色底、米白字、5px 圆角；次按钮：透明底、虚线边框。
- 底部导航：纸张底色、顶部 2px 虚线、当前项铁锈色。
- 弹层：底部抽屉式，圆角 10px，遮罩为半透明暖黑。
- 提示：底部浮层 Toast，3 秒自动消失，不遮挡导航。

## 6. 数据模型（IndexedDB）

数据库名 `wardrobe-db`，版本 1。

### 6.1 `items`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | UUID |
| code | number | 展示用编号，创建时取当前最大值 + 1 |
| name | string | 必填，≤ 60 字 |
| category | string | 分类名称 |
| color | string | 颜色名称 |
| seasons | string[] | `spring/summer/autumn/winter` |
| occasions | string[] | `daily/work/date/sport/formal/home` |
| brand | string | 可选，≤ 40 字 |
| note | string | 可选，≤ 500 字 |
| photoId | string \| null | 关联 `photos.id` |
| favorite | boolean | 是否收藏 |
| createdAt | string | ISO 时间 |
| updatedAt | string | ISO 时间 |

索引：`category`、`favorite`、`createdAt`、`updatedAt`。

### 6.2 `photos`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | UUID |
| thumb | Blob | 最长边 400px，JPEG 质量 0.75 |
| full | Blob | 最长边 1200px，JPEG 质量 0.82 |
| width | number | 原图宽度 |
| height | number | 原图高度 |
| createdAt | string | ISO 时间 |

### 6.3 `outfits`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | UUID |
| code | number | 展示用编号，创建时取当前最大值 + 1 |
| name | string | 必填，≤ 60 字 |
| itemIds | string[] | 至少 1 件 |
| seasons | string[] | 同上 |
| occasions | string[] | 同上 |
| note | string | 可选，≤ 500 字 |
| favorite | boolean | 是否收藏 |
| createdAt | string | ISO 时间 |
| updatedAt | string | ISO 时间 |

索引：`favorite`、`createdAt`。

### 6.4 `wearLogs`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | UUID |
| date | string | 本地日期 `YYYY-MM-DD`，唯一索引 |
| outfitId | string \| null | 来源搭配，可为空 |
| outfitName | string | 保存时的搭配名称快照 |
| itemIds | string[] | 保存时穿的单品 ID 快照 |
| itemNames | string[] | 保存时的单品名称快照 |
| note | string | 可选，≤ 300 字 |
| weather | string | 可选，如 `晴/阴/雨/冷/热` |
| createdAt | string | ISO 时间 |
| updatedAt | string | ISO 时间 |

索引：`date`（unique）、`createdAt`。

### 6.5 `settings`

键值存储，keyPath 为 `key`：

- `categories`：分类数组，默认 `["上装","下装","连衣裙","外套","鞋","包","配饰","其他"]`。
- `colors`：颜色数组，默认 `["黑","白","灰","米","棕","红","粉","橙","黄","绿","蓝","紫","花色"]`；名称到色值的映射定义在前端常量中。
- `lastBackupAt`：最近一次成功导出的时间。
- `schemaVersion`：数据版本，当前为 1。

### 6.6 统计规则

- 单品穿着次数：统计 `wearLogs.itemIds` 中包含该单品的记录数，使用快照数据。
- 最近穿着：该单品在记录中出现的最大日期。
- 闲置：最近 90 天内没有出现，且录入时间超过 90 天；从未穿过但录入不足 90 天的不算闲置。
- 本月统计：按 `date` 前缀过滤当月记录。
- 统计在使用时实时计算，不额外存表。

### 6.7 编号与引用完整性

- 单品与搭配的 `code` 在创建时取当前最大值 + 1；删除后不重新编号，编号只用于展示。
- 删除单品时，同时删除其 `photos` 记录，并从所有搭配的 `itemIds` 中移除该 ID；因此变空的搭配保留，但详情页提示「需要补充单品」。
- 删除搭配不影响历史记录：`wearLogs` 保存了 `outfitName` 与 `itemIds` 快照，`outfitId` 允许指向已删除的搭配。
- 在设置中重命名分类或颜色时，同步更新所有引用旧值的单品；删除只从预设列表移除，不修改历史数据。

## 7. 技术架构

### 7.1 技术选型

- HTML + CSS + 原生 JavaScript（ES Modules），无框架、无构建、无第三方运行时依赖。
- 哈希路由（`#/wardrobe`、`#/item/:id` 等），适配 GitHub Pages 等静态托管的子路径。
- IndexedDB 存储结构化数据与图片 Blob。
- Service Worker 预缓存应用外壳，实现离线访问。
- Web App Manifest 提供安装能力与桌面图标。
- 所有资源同源加载；无外部字体、CDN、统计脚本与网络 API。

### 7.3 分层职责

- `db/`：只负责 IndexedDB 的打开、读写与事务，不包含 UI 逻辑。
- `store.js`：内存中的当前列表与筛选状态，负责通知视图刷新。
- `views/`：每个页面一个模块，负责渲染与事件绑定。
- `components/`：可复用的导航、弹层、Toast、图片输入、空状态。
- `utils/`：纯函数工具，优先用 Node 内置测试覆盖。

### 7.4 图片处理

1. 用户拍照或选图后，用 `createImageBitmap(file, { imageOrientation: "from-image" })` 读取，自动处理 EXIF 方向；失败时回退到 `Image` 元素。
2. 用 Canvas 缩放并导出两个 Blob：
   - `thumb`：最长边 400px，JPEG 0.75；
   - `full`：最长边 1200px，JPEG 0.82。
3. 先写入 `photos`，再保存 `items.photoId`；若单品保存失败，删除孤立图片。
4. 解码失败时提示「这张图片格式暂不支持，请换一张」，不创建单品。

### 7.5 PWA 与缓存

- `manifest.webmanifest`：名称「我的衣橱」、短名「衣橱」、`display: standalone`、`start_url: "./"`、`scope: "./"`、主题色与背景色为 `#F5E6C8`。
- 图标：192、512 与 maskable 512 PNG，另保留 SVG 源文件。
- Service Worker：
  - 安装时缓存应用外壳（HTML、CSS、JS、图标、manifest）。
  - 激活时清理旧版本缓存并接管页面。
  - 导航请求失败时回退到缓存的 `index.html`。
  - 新版本激活后提示「有新版本，刷新后生效」。
- 启动时调用 `navigator.storage.persist()`，降低浏览器在空间紧张时清理数据的概率。

### 7.6 安全与隐私

- 不发起任何业务网络请求；应用可在断网状态下完整使用。
- 页面设置 CSP：`default-src 'self'; img-src 'self' blob: data:; style-src 'self' 'unsafe-inline'; script-src 'self'; connect-src 'none'`。
- 导出的备份文件包含个人照片，界面上明确提示妥善保管。
- 无第三方代码、无遥测。

## 8. 关键流程

### 8.1 录入单品

1. 点击「＋」→ 打开拍照/相册选择。
2. 选图后本地压缩，展示预览。
3. 填写名称、分类、颜色、季节、场合等。
4. 保存：写图片 → 写单品 → 关闭表单 → 回到衣橱并刷新列表。
5. 失败时回滚已写入的图片，显示错误提示。

### 8.2 创建搭配

1. 点击「新建搭配」。
2. 填写名称，从衣橱多选至少一件单品。
3. 选择季节、场合，可填备注。
4. 保存后生成拼贴封面（取前 4 件单品的缩略图）。
5. 返回搭配列表。

### 8.3 记录穿着

1. 在记录页选择日期，或从搭配详情点「今天穿这套」。
2. 选择已有搭配，或临时选择单品。
3. 保存时写入单品 ID 与名称快照、搭配名称快照。
4. 同一天已有记录时，进入编辑而不是新增。
5. 日历与统计立即刷新。

### 8.4 导出与导入

- 导出：读取全部数据，图片转 base64，生成带 `app`、`schemaVersion`、`exportedAt` 的 JSON，通过下载触发保存；成功后更新 `lastBackupAt`。

导出文件结构：

```json
{
  "app": "wardrobe-pwa",
  "schemaVersion": 1,
  "exportedAt": "2026-11-03T10:00:00.000Z",
  "data": {
    "items": [],
    "outfits": [],
    "wearLogs": [],
    "settings": [],
    "photos": [
      {
        "id": "uuid",
        "thumb": "data:image/jpeg;base64,...",
        "full": "data:image/jpeg;base64,...",
        "width": 1200,
        "height": 1600,
        "createdAt": "2026-11-03T10:00:00.000Z"
      }
    ]
  }
}
```

- 导入：
  1. 选择 JSON 文件并解析。
  2. 校验 `app`、`schemaVersion`、必需字段与图片数据格式；先把 base64 解码为 Blob，解码失败视为文件损坏。
  3. 弹窗要求确认「将覆盖当前全部数据」，并提供「先导出一份」入口。
  4. 在单个 IndexedDB 事务中清空并写入所有 store；任一步失败则事务回滚，原数据保持不变。
  5. 重新加载页面数据并提示导入结果。

## 9. 错误处理

- IndexedDB 无法打开：全屏错误页，提供「重试」按钮与排查提示。
- 存储空间不足：提示已用空间与单品数，建议导出备份后删除不常用单品的图片。
- 图片解码失败：提示更换图片，不产生脏数据。
- 导入格式错误：弹窗说明具体原因（缺少字段、版本过高、图片数据损坏），不写入任何数据。
- 删除单品/搭配/记录：二次确认；删除单品时一并删除其主图，并清理搭配中的引用。
- Service Worker 注册失败：应用仍可在线使用，显示轻提示。
- 全局未捕获错误：显示通用错误 Toast，并保留当前页面状态。

## 10. 测试策略

### 10.1 自动化测试

使用 Node 内置测试运行器（`node --test`），无需安装依赖。覆盖纯逻辑：

- `dates.js`：本地日期格式化、月份网格生成、周一起始、跨月边界。
- `stats.js`：穿着次数、最近穿着、90 天闲置判断、月度统计。
- `backup.js`：导出结构、导入校验、错误版本与损坏数据。
- `filters.js`：关键词、分类、季节、场合组合筛选与排序。

UI 与 IndexedDB 交互以手动验收为主，不引入浏览器测试框架。

### 10.2 手动验收清单

1. 手机 Chrome 打开线上地址，可添加到主屏幕并以独立窗口启动。
2. 录入带照片的单品，刷新页面后仍在。
3. 创建搭配，封面拼贴正确显示。
4. 记录今天穿着，日历出现圆点，统计数字正确。
5. 同一天再次记录时进入编辑模式。
6. 搜索、分类/季节/场合筛选、三种排序均正确。
7. 导出备份 → 清空数据 → 导入备份，单品、搭配、记录、照片全部恢复。
8. 断网后仍能浏览全部页面与已有数据。
9. 375px 宽度无横向滚动；按钮触控区域不小于 44px。
10. 浏览器开发者工具中无第三方网络请求。

## 11. 部署

- 构建产物即源码，无需打包。
- 部署到 GitHub Pages 或 Cloudflare Pages 的免费静态托管。
- `README.md` 写明两种部署方式、如何更新、如何在安卓 Chrome 添加到主屏幕、如何备份数据。
- 首次加载需要网络；之后由 Service Worker 提供离线访问。

## 12. 验收标准

- 三大核心功能（单品、搭配、记录）形成完整闭环，均可新增、编辑、删除。
- 数据在关闭浏览器、重启手机后仍然存在。
- 备份可完整往返，照片不丢失。
- 无后端、无账号、无网络请求，成本为 0。
- 视觉与「E · 胶片日记」规范一致，移动端无横向滚动，触控与对比度达标。
- 纯逻辑测试全部通过。
